# 后端运行说明

项目尚未上线。后端由 `common`、`entity`、`server` 三个模块组成，`server` 是唯一启动应用。HTTP 根路径为 `/api/v1`，默认端口 5922；接口按 Admin、Blog、Home、Cv 分端，详见[接口索引](API_INDEX.md)。

## 构建和启动

需要 JDK 21、Maven、MySQL 8.0.16+ 和 Redis。从仓库根目录构建：

```powershell
mvn -B -ntp -f Backend/pom.xml package
```

构建生成 `Backend/server/target/server-2.0.0-SNAPSHOT.jar`。没有启动应用、数据库或第三方服务时，构建只能验证编译和打包。

数据库结构、字段、权限和菜单种子统一维护在 [SQL 基线](../sql/drifting_leaves_v2.sql)。只向新建空库人工导入，不提供增量迁移脚本。不要对已有开发数据重复导入；应用不自动建库、迁移、创建管理员或导入演示数据。

## 环境配置

`Backend/server/src/main/resources/application*.yml` 按现有 `.gitignore` 保持本地文件，不进入 Git。新检出仓库需要自行准备这些文件或 Spring Boot 外部配置，不要依赖其他机器上的默认连接。

| 文件 | 职责 |
| --- | --- |
| `application.yml` | 环境选择、HTTP、线程、连接池、SMTP、MyBatis、Sa-Token 等公共配置 |
| `application-dev.yml` | 开发环境的连接、站点、存储和 OAuth 参数 |
| `application-prd.yml` | 后续部署使用的环境参数，环境名为 prd |

默认环境为 dev。可通过 `SPRING_PROFILES_ACTIVE` 或 `--spring.profiles.active=prd` 覆盖。修改配置后需重新启动对应后端；打进 jar 的配置还需重新构建。

| 环境变量 | 用途 |
| --- | --- |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | V2 数据库连接，MySQL 会话使用 UTC |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DATABASE` / `REDIS_PASSWORD` | Redis 连接 |
| `REDIS_KEY_PREFIX` | 隔离环境的会话、OAuth、限流和缓存；本地 dev/test 前缀分别为 `dl:v2:dev:` / `dl:v2:test:` |
| `SERVER_PORT` | 默认 5922，context-path 固定 `/api/v1` |
| `FRONTEND_ORIGINS` | 旧的绝对附件地址兼容列表，只用于识别已保存的本站附件地址 |
| `HOME_BASE_URL` / `BLOG_BASE_URL` / `CV_BASE_URL` | 与实际访问来源和路径一致的公开站点基址，生产 Blog 必须使用 HTTPS |
| `ADMIN_BASE_URL` | Admin 网页基址，后端据此校验来源。生产必须使用 HTTPS |
| `PUBLIC_API_BASE_URL` | 公开 API 基址，用于生成附件和订阅等地址 |
| `TRUSTED_PROXIES` | 明确信任的代理 IP；默认空，不直接信任任意转发头 |
| `BCRYPT_STRENGTH` | 默认 12；上线前在目标硬件校准 |
| `AUTH_RATE_WINDOW_SECONDS` / `AUTH_RATE_LOGIN_FAILURES` / `AUTH_RATE_REGISTER` / `AUTH_RATE_OAUTH` | 认证限流参数，其他阈值见[接口文档](API.md#common) |
| `UPLOAD_ROOT` / `FILE_PUBLIC_ORIGINS` | 临时/本地文件目录与明确的本站 API 来源 |
| `OSS_ENABLED` / `OSS_ENDPOINT` / `OSS_REGION` / `OSS_BUCKET` / `OSS_KEY_PREFIX` | 对象存储开关和目标配置 |
| `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` / `OSS_SECURITY_TOKEN` | 对象存储凭据及可选临时安全令牌 |
| `IMAGE_COMPRESS_ENABLED` / `IMAGE_COMPRESS_MAX_SIZE_KB` / `IMAGE_COMPRESS_QUALITY` / `IMAGE_COMPRESS_MAX_DIMENSION` | PNG/JPEG 新上传压缩，默认目标 500 KiB、JPEG 质量 0.9、最长边 2560 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USERNAME` / `SMTP_PASSWORD` | SMTP 连接与授权 |
| `MAIL_ENABLED` / `MAIL_FROM` / `MAIL_FROM_NAME` | 邮件业务开关、发件地址及显示名 |
| `MAIL_CONFIRM_URL` / `MAIL_UNSUBSCRIBE_URL` | 博客确认/退订页面，不含 query 或 fragment |
| `OAUTH_COMPLETE_URL` | 固定 `https://<所选端>/oauth/complete`，与该端注册回调同源 |
| `OAUTH_GITHUB_*` / `OAUTH_GITEE_*` / `OAUTH_QQ_*` | 各平台的 ENABLED、CLIENT_ID、CLIENT_SECRET、REDIRECT_URI |

本地 `dev` 默认使用 `http://127.0.0.1`。Home 端口为 5173，Blog 为 5174，Cv 为 5175，Admin 为 5176。Chrome 已验证可以在此回环地址保存和发送 `Secure` Cookie。需要本地 HTTPS 时，按两端 README 配置证书，并将站点基址改成浏览器实际访问的地址。更换主机名、端口或协议后重启后端，配置来源须与实际来源一致。

### 网页会话配置

生产环境的 Admin 与 Blog 使用不同 HTTPS 主机名。各自站点将 `/api/v1/admin/` 或 `/api/v1/blog/` 原样转发到后端，保留请求 Origin、Referer 和 HTTP 会话 Cookie，以及响应的 Set-Cookie。Blog 的 `/api/v1/blog/ws/online` 支持 Upgrade，转发握手时移除 Cookie。代理不记录 Cookie、Set-Cookie 和 OAuth 回调参数。

本站使用 Sa-Token 与 Redis 鉴权。HTTP 跨域仅对 Home、Cv 各自的公开接口和配置来源开放。沿用本地配置时，合并以下公共 Sa-Token 配置并删除旧的 `token-prefix: Bearer`。`token-name: Authorization` 保留 Redis 键名，HTTP 不读取该头。

```yaml
sa-token:
  token-name: Authorization
  is-read-body: false
  is-read-header: false
  is-read-cookie: false
  is-write-header: false
  timeout: 259200
  active-timeout: -1
  auto-renew: false
  is-concurrent: true
  is-share: false
  right-now-create-token-session: true
```

两个环境按实际 HTTPS 基址配置 `app.sites.admin-base-url` 与 `app.sites.blog-base-url`。前后端同时切换，启动时清除旧网页存储值，已登录的用户需重新登录。旧 Redis 会话随原 TTL 到期。

启动示例，连接和凭据由当前环境提供：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'dev'
java -jar Backend/server/target/server-2.0.0-SNAPSHOT.jar
```

## 数据源

使用 `druid-spring-boot-4-starter`，已排除 HikariCP。公共配置采用以下连接池参数，连接地址和凭据另行配置：

```yaml
spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    druid:
      initial-size: 5
      min-idle: 5
      max-active: 20
      max-wait: 60000
      connection-init-sqls:
        - SET time_zone = '+00:00'
      default-transaction-isolation: 2
      validation-query: SELECT 1
      validation-query-timeout: 2
      test-while-idle: true
      test-on-borrow: false
      test-on-return: false
      stat-view-servlet:
        enabled: false
      web-stat-filter:
        enabled: false
```

JDBC 隔离级别 2 表示 READ COMMITTED。应用入口使用 UTC，HTTP 时间为 UTC 毫秒。业务表的审计时间由数据库维护，MyBatis 一级缓存限定为 STATEMENT。

## 文件、邮件与 OAuth

- OSS 默认启用，缺少必要凭据会拒绝启动。文件按“分类目录/随机文件名”存储，不支持旧版平铺对象键。PNG/JPEG、音频和歌词的实际限制见[接口文档](API.md)，文件分类不等于上传白名单。
- 私密文件不放进公开静态目录；文章和音乐附件通过对应 API 校验权限、引用及可见性。文件仍被引用时禁止删除，上传后数据库失败会尝试清理对象；MySQL 与对象存储没有共同事务。
- `UPLOAD_ROOT` 需可写，用于临时校验及配置的本地存储；不自动移动或删除已有对象和开发数据。
- SMTP 必须提供有效账号和授权。验证码与确认申请同步发送，失败返回错误；发布、回复通知使用虚拟线程和现有并发限制，仍是进程内投递。确认/退订前端页面已存在，真实邮箱投递和客户端显示需要单独验证。
- OAuth 仅支持配置完整且启用的平台。先邮箱注册，再登录绑定第三方；未绑定第三方不能自动注册，后台第三方 LOGIN 禁止。
- 同源调用 authorize/exchange。后端只启用回调和完成页同源、路径匹配的配置。例如博客使用 `OAUTH_COMPLETE_URL=https://blog.example.com/oauth/complete` 和 `OAUTH_GITHUB_REDIRECT_URI=https://blog.example.com/api/v1/blog/auth/oauth/GITHUB/callback`，在 GitHub 登记相同回调。选择 Admin 时两处都改为 Admin HTTPS 主机名，回调路径改为 `/api/v1/admin/auth/oauth/GITHUB/callback`。一套部署只配置一个完成页。
- OAuth 流程 Cookie 为 Secure、HttpOnly、SameSite=Lax。回调核对 state、浏览器和服务端保存的原会话，完成页清除 fragment 并按同源窗口传票据。BIND 只返回绑定结果。
- Blog/Admin 登录 Cookie 分别固定有效 3 天/7 天，均为 host-only、HttpOnly、Secure、SameSite=Strict、Path=/。JSON 只返回 `expiresIn` 和 `user`。刷新重查身份和权限，退出先撤销会话再清除 Cookie。写请求核对本端 Origin，缺失时才解析 Referer。

## 公开缓存与 Redis

公开查询缓存使用 Spring Cache 和专用序列化器；鉴权、权限、私密内容、票据和附件字节不进入公共缓存，HTTP `no-store` 保持不变。缓存域、TTL 和失效范围见[接口文档](API.md#common)及 [PublicCacheConfig](../Backend/server/src/main/java/com/xuan/config/PublicCacheConfig.java)。

读取在事务快照前取得缓存代次，写入在首次修改 SQL 前登记事务保护。成功提交后切换受影响域的代次并移除自身保护，回滚只移除自身保护。读取/回填故障可以回源；会话、限流、票据等安全 Redis 故障仍返回错误。提交后缓存失效失败时数据库可能已提交，应先查询最新结果，不能自动重放写入。

Redis 故障、恢复备份或进程中断后，若有遗留 `<域>:writers`：

1. 相关域继续旁路，不直接删除标记恢复命中。
2. 停止外部流量及所有应用写入实例，确认数据库事务已结束。
3. 为全部公开缓存域轮换全新 generation；可以在无流量时启动单个实例完成轮换，启动操作会保留 writers。
4. 确认无存活写事务后，仅清理已确认遗留的 writers 成员或键，再恢复服务。旧数据键等待 TTL 回收，不清除会话、限流、OAuth 或订阅命名空间。

## 实时在线人数

当前只支持单后端实例。Home、Blog、Cv 参与，只有 Blog 展示三端合计；Admin 不参与。Redis 存短期在线票据，成员及广播在进程内，重启后随浏览器重连恢复。多实例部署前需要共享成员和跨节点广播。

三端开发代理已配置 `ws: true`。后续反向代理需保留原始路径、Origin 和 Upgrade：

```nginx
location ~ ^/api/v1/(home|blog|cv)/ws/online$ {
    proxy_pass http://127.0.0.1:5922;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Origin $http_origin;
}
```

在线心跳不延长登录会话，不写 PV/UV。消息、心跳与关闭码见[在线说明](实时在线人数接口说明.md)。
