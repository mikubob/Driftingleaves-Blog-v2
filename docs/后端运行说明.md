## 构建和启动

需要 JDK 21、Maven、已人工初始化的 V2 MySQL 空库和独立 Redis。应用不运行 SQL 初始化、迁移或自动创建账号。SQL 基线仅供空库受控执行；不要向已有业务库重复导入。

在项目根目录构建：

```powershell
mvn -B -ntp -f Backend/pom.xml verify
```

这条普通命令运行无外部服务单测；未指定隔离程序路径时，`IdentityIntegrationTest`、`ArticleIntegrationTest` 和 `OnlineIntegrationTest` 明确跳过。完整隔离验证命令见下节。

配置分为主控制和三个环境文件，位于 `Backend/server/src/main/resources/`：

| 文件 | 职责 |
| --- | --- |
| `application.yml` | 选择环境，并维护端口、上传限制、线程、连接池、SMTP认证/TLS/超时、MyBatis、Sa-Token及日志等公共设置 |
| `application-dev.yml` | 开发环境的数据库、Redis、邮箱、站点、OSS和OAuth参数 |
| `application-test.yml` | 测试环境的同类参数；隔离集成测试显式选择此环境，继续动态覆盖临时MySQL/Redis和存储配置 |

## 文章聚合与附件引用

第 7 章使用 `IArticleService/ArticleServiceImpl`、`ArticleMapper/XML` 及独立前后台 Controller。所有公开入口固定检查发布、公开、未回收和首次发布时间；隐藏分类只隐藏分类投影，按隐藏/不存在分类筛选为空页。关键词通过参数化 INSTR 对标题、摘要和 Markdown 字面包含，百分号、下划线、反斜线不作为通配符；月份采用 UTC 半开区间，9999-12 只设下界。公开列表、后台列表及归档使用各自固定顺序和主键，后台 authorId 只能附加筛选。

后台写事务先锁操作者行，防止原会话校验跨过生产授权撤销点；再按 fileId 升序锁旧/新文件集合，最后锁文章。锁后重读当前正文、完整标签和元数据，复核原 Token、最新操作权限及 SQL 作者范围；已发布文章编辑另行满足 publish 权限及其独立范围。`local-cache-scope=STATEMENT` 避免 MyBatis 一级缓存重用锁前正文或授权，READ COMMITTED 的复查才能读取最新提交值。详情版本覆盖全部业务元数据、状态、首次发布时间、回收时间、Markdown 和升序 tagIds，排除计数、审计时间、HTML 缓存及阅读派生字段。标签父字典及当前关联在版本检查前保持共享锁，阻止删除级联穿过检查点。唯一冲突返回脱敏 409，锁超时/死锁等数据库失败整笔回滚并返回 503。

草稿作者固定会话用户、status=0。完整 PUT 不接受身份、HTML、状态、发布时间或计数；空值真实清空可空字段。首次发布写服务端 UTC，后续保留；回收只写 deletedAt，恢复固定下架且保留首次发布时间。文章元数据、正文、安全 HTML、完整标签以及成功审计共同提交；成功日志失败也使文章回滚。没有给文章写入增加未声明的限流阈值，继续沿用现有请求上限、身份/权限和审计约定。

正文始终经现有 CommonMark/jsoup 重新渲染清理，数据库 HTML 缓存不作为可信输入。公开详情仅投影安全 HTML 和公开资料，按可见文字派生字数/阅读分钟；上下篇、同分类最多六篇推荐和热门榜均固定 PUBLIC，查询候选不计阅读。只有公开详情成功才在文章锁内原子递增 view_count，失败回滚，保留 update_time 和 X-Revision。点赞按明细 COUNT，评论只读取链结构/状态并迭代核验完整祖先链，排除待审、驳回、占位及隐藏后代，不受 MySQL 默认递归 CTE 深度限制。本月热门榜只筛本月首次发布候选，排序指标仍是累计阅读或当前点赞数量；没有实现第 19 章访问统计。

附件只接受当前文章的 `/api/v1/blog/articles/{articleId}/files/{fileId}/content`。创建前没有 articleId，不能带本站附件；编辑解析 Markdown AST 和清理后实际保留的 HTML 链接/图片，普通文本/代码块中的相同字符串不算引用。明确本站 origin 的等价绝对 URL 在 HTML 和封面中归一为公开相对路径，Markdown 源不改写；跨篇、编码、路径归一化、后台附件路径和已配置 OSS 直链绕过均拒绝。结果引用要求文件元数据存在、`blog:file:query` 及独立 SQL 上传者范围，同时核验本地根内真实对象或已配置私有 OSS 对象可用；发布再次检查。移除引用仍锁旧文件，不能因文件对象缺失而阻止移除或下架。

后台详情 HTML 把规范附件属性改成后台文章上下文，外部地址、正文文本和代码示例保持原值；coverUrl 保留可直接用于完整 PUT 的规范公开相对值。后台预览封面需转换为对应后台上下文并用 Bearer fetch，再生成临时 object URL。第 11 章已经提供上述文件 HTTP 入口，内容每次都按当前状态与引用检查，原图读取不增加文章阅读计数；浏览器 Bearer fetch/object URL 联调尚未执行。云 SDK 存在性检查已覆盖边界替身，未使用真实云账号。

### 文件上传、读取与删除（第 11 章）

七个入口由前后台 FileController、IFileService/FileServiceImpl、FileMapper/XML 提供，复用现有 ArticleResources、FileProperties、UrlPolicy、AliOssClient 和条件装配，不新增依赖、表、文件用途或可见性字段，也不为不可变元数据添加版本。文件 query/upload/delete 固定权限禁止删除，最后管理员保护名单不扩大。

上传仅收一个 file 部件，PNG/JPEG 单文件非空且不超过 10MiB，multipart 总请求不超过 11MiB；声明 Content-Type 不可信，扩展名须匹配 ImageIO 识别结果。先检查宽高各不超过 10000、总像素不超过 2500 万，再实际解码；原文件名移除路径分隔符和控制字符，仅用于展示。临时文件在UPLOAD_ROOT下创建，验证后默认上传私有OSS对象并清理临时文件，目录仍需可写；显式关闭OSS时才使用本地原子移动。数据库、成功审计或提交失败时清理新对象；补偿失败输出固定运维错误，孤立对象需人工检查。没有成功元数据的对象无法通过 API 访问。入口用现有 RedisRateLimiter 按用户及可信 IP 共用每 60 秒 10 次窗口，429 带 Retry-After，Redis 不可用则 503。

元数据只返回 File 模型，不含 bucket、objectKey 或内部路径。后台原图检查文件 query 上传者范围，与文章公开状态无关；后台文章附件分别检查文章 query 和文件 query 的 SQL 范围。公开附件固定检查当前 PUBLIC 文章及 Markdown/封面真实引用，持有管理员 Token 也不放宽。文件锁早于文章锁，等待后重新检查原 Token、身份、权限、范围与状态；图片在锁事务里有界读取完成并关闭存储流，再返回实际 Content-Length、确认 MIME、UTF-8 inline 文件名、nosniff 和 no-store，不返回延迟读取流或存储直链。

删除先锁操作者、再锁文件，锁内按 articleId 每批 100 篇解析全部文章的 Markdown 和封面，包括草稿、私密、下架和回收站；不使用 HTML 缓存或文本数字匹配，不新增引用表。仍有引用返回 409；扫描和新增引用共用文件锁，不能同时提交悬空引用。无引用时先删对象，失败保留元数据返回 503；对象已不存在也允许继续删元数据。对象已删而元数据或审计提交失败时，读取返回 503，重试 DELETE 可以完成清理。文件系统/OSS 与 MySQL 不具有共同事务。上传根目录必须位于静态资源映射之外，现有本地对象不因开启 OSS 自动迁移。

### IP 转地域地址

按用户后续要求引入 `org.lionsoul:ip2region:3.3.7`，父POM统一版本，common声明依赖。核对[官方Java查询用法](https://github.com/lionsoul2014/ip2region/blob/master/binding/java/README_zh.md)和实际发布Jar：客户端不依赖Spring/Jackson，使用其并发安全的双协议 `Ip2Region` API，已在本项目Java21、Boot4下编译和装配，不升级框架。

`common/location/IpLocationResolver` 是可注入的有状态组件，由 `server/config/IpLocationConfig` 从classpath资源流加载。两份旧项目公共xdb原样复制到 `common/src/main/resources/ip2region/`，附来源、SHA-256和上游许可；不是业务数据。IPv4/IPv6分别约10.6MB/36.1MB，默认随common.jar及可执行应用打包，无须额外环境变量。使用BufferCache，约47MB数据常驻内存，查询不访问磁盘、DNS或外部定位服务；不按请求创建/关闭查询器。启动时校验资源完整性和协议版本，失败阻止组件启动；预先核对头部，规避3.3.7流加载协议错配时的空文件异常路径。输入流立即关闭，查询器由容器统一close。

业务按需注入 `IpLocationResolver`，先用 `IpUtils.clientIp(request, authProperties.getTrustedProxies())` 取得可信IP，再调用：

```java
IpLocationResolver.GeoInfo geo = ipLocations.getGeoInfo(ip);
// geo.country() / geo.province() / geo.city()；未知字段为 null。
String address = ipLocations.getIpLocation(ip);
// 例如 114.114.114.114 -> 江苏省 南京市。
```

3.x配套库字段为 `国家|省份|城市|ISP|国家代码`，只读取前三项，不套用旧2.x位置；保留库中地名，不自动翻译。缺失或`0`字段归一为null；无效/未命中地址展示“未知”，IPv4/IPv6回环展示“本地”。省市为空时展示国家。查询故障返回脱敏503，线程中断保留中断标志，不伪装成正常未知结果。

这是IP出口归属地域估计，不能提供设备实时坐标或街道地址；局域网/保留地址可能只返回库内的Reserved。当前仅提供共享工具，不改SQL、不新增地域HTTP接口，不把地域结论用于授权或自动写入现有日志。更新时替换双协议源资源、同步指纹说明、重新构建并重启，见[资源说明](../Backend/common/src/main/resources/ip2region/README.md)；不自动下载或热更新。

## OAuth 配置与前端衔接

白名单为 GITHUB、GITEE、QQ，默认全部关闭。只有 enabled=true、client-id/client-secret/固定回调和固定完成页全部有效才列入 providers；不会返回 App 凭据。每平台只配置一个应用，不能由客户端传 redirectUri、uuid 或 userId。

| 环境变量 | 示例/说明 |
| --- | --- |
| OAUTH_COMPLETE_URL | `https://blog.example.com/oauth/complete`，必须属于 FRONTEND_ORIGINS，HTTPS，无 query/fragment |
| OAUTH_GITHUB_ENABLED | 默认 false |
| OAUTH_GITHUB_CLIENT_ID / OAUTH_GITHUB_CLIENT_SECRET | 对应平台应用凭据 |
| OAUTH_GITHUB_REDIRECT_URI | 例如 `https://api.example.com/api/v1/blog/auth/oauth/GITHUB/callback`，也可配置 `/api/v1/admin/auth/oauth/GITHUB/callback`；必须同步平台回调白名单，旧 `/api/v1/auth` 路径已移除 |
| OAUTH_GITEE_* / OAUTH_QQ_* | 同样的 ENABLED、CLIENT_ID、CLIENT_SECRET、REDIRECT_URI 字段，回调路径使用对应大写 source |

前后端需同站 HTTPS，推荐同源 `/api` 反代。浏览器 Cookie 为 `__Host-dl-oauth-browser`，Secure、HttpOnly、SameSite=Lax、Path=/、无 Domain、600 秒；仅绑定浏览器，不代表登录。所有 authorize/exchange 请求必须带精确 Origin（浏览器自动发送）和 `credentials: 'include'`。

LOGIN：前端 POST authorize `{operation:'LOGIN'}`，导航返回的 authorizationUrl。后端校验并原子消费 300 秒 state 后换码，事务注册或查询本站账号，再跳固定完成页 `#ticket=...`。完成页立即读取 fragment 并 `history.replaceState(null, '', '/oauth/complete')` 清除票据，以 credentials POST exchange `{ticket}`。60 秒 ticket 一次性，返回 `{operation:'LOGIN',session}`；Token 和固定到期时间由前端按端保存在 localStorage（博客 3 天、管理端 7 天），刷新后向后端核验身份与权限，不续期。

BIND：原页面先保留当前内存 Token，准备授权弹窗，再带该 Bearer 发起 `{operation:'BIND'}`，将弹窗导航到 authorizationUrl。弹窗完成页读取 ticket、清除 fragment，并通过 `window.opener.postMessage` 只传本次票据到精确的前端 targetOrigin。原页面必须校验 `event.origin`、`event.source === 刚打开的弹窗` 及待处理流程，再携带**发起时同一个 Token**和 credentials 兑换；结果只含 `{operation:'BIND',binding}`，不返回新会话。另一个相同用户 Token 也不能兑换。弹窗不接收本站 Token；不通过 URL、Cookie 或 postMessage 传 Token；持久凭据仅由原页面的会话模块管理。

可信流程失败回跳 `#error=<业务码>`，不透传平台描述；无可信浏览器/state 关系时直接返回 JSON 错误。同浏览器支持多个 state。原页面刷新、关闭或原 Token 过期后不能凭 Cookie 恢复身份；重新登录后先查绑定列表确认。回调绑定已提交但 ticket 丢失时也通过绑定列表确认。

源码的 JustAuth 网关执行原有 code/state 校验、换码和身份解析，跳过会打印原始平台异常的 login 包装层；平台网络异常由协调层脱敏为 OAUTH_UPSTREAM_ERROR。本期用边界替身验证 GitHub 响应解析，不代表 QQ/Gitee 或任何真实 App 已完成平台联调。

## 并发、安全和实体边界

- 密码/身份写事务为 READ COMMITTED。注册用户+member、OAuth 用户+绑定+member 同事务；唯一冲突整笔回滚再查询赢家。实体不直接作为用户响应。
- 登录、密码、绑定和解绑使用同一用户行锁。密码变更和解绑先完成 Redis 全会话撤销，再提交数据库；失败回滚数据库，数据库提交失败可能已经退出登录。登录提交失败清理本次 Token，MySQL 与 Redis 不构成共同事务。
- OAuth 票据兑换在用户锁内重查原 source+uuid 仍绑定同一用户，避免待兑换票据恢复已解绑身份。认证时间为平台验证成功时间，不因票据等待刷新。
- 最近认证保存在 Token 级会话，窗口 300 秒；纯第三方首设密码须最近 OAuth 登录。密码 8..64 Unicode 字符、UTF-8 最多72字节，不 trim 或截断。最后登录方式只计算有效密码和当前配置可用平台绑定。
- 资料版本摘要包含资料、状态与完整 roleIds，排除密码及审计/登录时间；本人及后台详情共用带引号 X-Revision，PATCH 和后台两个 PUT 在锁内校验单个 If-Revision。缺失 428、过期 412、格式不合法 400。
- 头像拒绝附件 API 路径及其等价绝对 URL，先解码并归一化路径；本人 PATCH 拒绝非法头像，OAuth 初始化丢弃非法头像。绑定查询只列当前配置完整且启用的平台，未启用绑定保留在库中，不计为可用登录方式。
- 授权与菜单每次读取数据库，不缓存旧权限；只有授予某权限的有效角色才能贡献该权限 ALL/SELF。菜单保留有权隐藏项/按钮，检查完整祖先链并去掉空目录。后续文章/文件 Mapper 仍须将资源归属落实到 SQL。后台用户及角色管理是全局操作，后台入口和具体业务权限缺一不可。
- 管理写事务先锁 `sys_role(role_id=1)`，再按用户 ID 升序锁操作者和目标，角色替换随后按角色 ID 升序加锁；等待后复核当前 Token、启用状态及双权限。禁用或移除 admin 关联时检查事务后的最后有效管理员，所需权限固定为 SQL 全部初始 `sys:*` 和 `admin:access`，不将新字典项自动加入。禁用及角色实际变化先完成 Redis 全会话撤销，再提交数据库；失败回滚。后台创建不分配角色，资料 PUT 不接受 username、password 或 roleIds。
- 角色写入复用相同固定保护锁，先按 ID 升序锁全部关联用户及操作者，再锁目标角色和本次权限。角色状态、范围或最终授权集合变化撤销全部关联用户会话，名称/说明变化及等价授权集合不撤销。内置角色不可删除，自定义角色删除级联清理三类关联；grants 共同替换权限和菜单，补齐祖先、校验启用与显式门禁，不自动扩大权限。
- 复合键表没有虚构单 ID；本文实现的角色关联写入使用明确 SQL。两个 UNSIGNED BIGINT 使用 BigInteger；站点 JSON 为原始 String，未来站点服务负责解析及键白名单。审计时间由数据库生成。

| 实际缓存域 | 数据 TTL | 内容 |
| --- | --- | --- |
| home、social、experiences、skills、links、music、configs | 1小时 | 对应公开展示及公开 site 配置 |
| categories、tags、authors、archives、rss、sitemap | 30分钟 | 当前字典/作者资料与计数、归档和 XML；索引/各子页分别入键 |

文章列表只复用集合和公开静态资料，本次 viewCount/likeCount/commentCount 从数据库补充；详情每次仍在原文章锁事务内检查 PUBLIC、当前正文与附件引用，成功才原子增加一次阅读。正文片段通过现有 `IArticleService` 的容器代理方法读取，避免同类直接调用使注解失效。公开评论每次先检查当前 PUBLIC 和请求父链，再经代理读缓存结果。`/blog/auth`、`/blog/me`、`/admin`、私密/本人留言、票据、采集写响应与附件字节均不进入这些公共缓存，HTTP `no-store` 保持不变。

### 提交、回滚与并发保护

[PublicCacheScope](../Backend/server/src/main/java/com/xuan/cache/PublicCacheScope.java) 在事务读取快照建立前捕获代次；已由外部事务建立快照的调用保守旁路缓存。[PublicCacheMutationInterceptor](../Backend/server/src/main/java/com/xuan/cache/PublicCacheMutationInterceptor.java) 在原业务加锁/校验之后、第一条真正修改 SQL 之前，按 Service 的 CacheEvict/Caching 声明登记本事务保护。登记失败返回503，数据库不提交。保护使用每事务随机标识组成的 Redis Set，**不设短 TTL**，并发事务只能移除自己的成员。

CacheEvict 的 `allEntries=true` 在事务提交后轮换整个域的随机代次并原子移除本事务保护；有保护时读取直接回源，不读/填旧数据。回填 Lua 还要确认快照前代次与当前代次一致、没有任何写保护，旧查询不能在提交后重新发布旧内容。旧代次数据键按原 TTL 回收，不使用 KEYS、FLUSHDB 或 FLUSHALL。成功写请求返回前完成所有声明域的失效；文章及字典的关联域覆盖旧/新 slug、所有筛选 total、导航/推荐、作者、RSS 和地图所有子页。

回滚只移除本事务保护，保持旧代次，不发布未提交数据；清理失败保留保护并记录固定运维错误，不替换原业务异常。纯缓存读/回填故障或结构不兼容可以回源，安全 Redis（会话、限流、票据）失败仍返回503。提交后失效失败也返回503，**数据库与成功审计可能已经提交**，客户端应先查最新状态/版本，不能自动重放写入。

### Redis 故障、恢复备份或进程中断后的处理

1. 保留相关 `<域>:writers` 标记。正常连通性恢复时，相应域继续旁路，不能仅删除标记来恢复命中。
2. 需要清除遗留标记或恢复 Redis 备份时，先停止接收流量并停止所有应用写入实例，确认这些实例的 MySQL 事务均已提交或回滚；未确认前保持旁路。
3. 为上表全部19个域的 `<域>:generation` 设置全新的、从未使用过的随机 UUID。可以在无外部流量时启动一个应用实例，由启动装配执行统一轮换；启动装配会保留遗留标记。若标记键结构损坏使启动拒绝，确认无写事务后通过运维控制台修复该键并轮换全部代次，再启动。
4. 代次轮换成功并确认无存活写事务后，仅删除已确认遗留的 `<域>:writers` 成员/键，再恢复流量。数据键保留原 TTL 自行回收。禁止顺带清理 session、rate、oauth 或订阅安全命名空间，也不能在应用继续服务时直接用旧 Redis 备份覆盖运行中的公共缓存状态。

本次测试模拟真实查询暂停、并发事务和 Redis 命令错误，不等同于真实主机断电或生产备份恢复演练；恢复步骤需要部署运维按上述停写边界执行。
