# 实时在线人数接口与实现说明

状态：已实现，首期单后端实例。更新日期：2026-11-01（Asia/Shanghai）。

现有 159 个 HTTP 业务路由基础上新增在线票据入口，合计 160 个 HTTP 路由，另有 1 个原生 WebSocket 入口。后端、前台登记与 Blog 展示已接入；不新增数据库表，不改变 PV/UV 或文章阅读统计。按用户最新要求，仅 Blog 的“站点统计”卡片展示人数，Home/Cv 匿名参与统计但不展示，Admin 不参与。

## 2. 统计范围与人数定义

首期默认统计 `home/blog/cv` 三个公开站点的全局合计，只在 Blog 的站点统计展示这组合计数字；Home/Cv 只匿名登记；`siteCode` 用于验证参与站点，不是查询筛选条件。后台管理端不建立统计连接，不计入在线人数。只登录后台、保有有效 Token 但未连接前台的人不算在线。

“在线”指连接已完成加入核验、尚未关闭且未超过心跳期限，不等同于鼠标活跃或自然人实时在场。后台标签页按同样规则参与，浏览器休眠导致超时后移除。

| 响应字段 | 类型 | 精确定义 |
| --- | --- | --- |
| `onlineCount` | string | 当前登录用户人数与当前未登录访客人数之和 |
| `userCount` | string | 至少有一个有效登录连接的不同本站 `userId` 数；同账号多标签页、多设备只计 1 人 |
| `guestCount` | string | 至少有一个匿名连接、且该浏览器统计键没有有效登录连接的不同浏览器统计键数 |
| `serverTime` | Time | 本次快照生成时间；UTC 毫秒 RFC 3339，沿用现有 API 约定 |

浏览器统计键为服务端核验后的 `(siteCode, Origin, fingerprint)`。登录连接也保存此键，以排除同键匿名标签页的重复计数。只在仍有有效连接的集合上统计，始终满足 `onlineCount = userCount + guestCount`，计数非负、无前导零，零值为 `"0"`。

| 场景 | 预期 `(onlineCount, userCount, guestCount)` |
| --- | --- |
| 无已加入连接 | `(0, 0, 0)` |
| 同站点、同 Origin、同 fingerprint 的两个匿名标签页 | `(1, 0, 1)` |
| 上一场景其中一页登录账号 A | `(1, 1, 0)`；匿名页仍是匿名身份，不获得任何账号权限 |
| 两个不同浏览器均登录账号 A | `(1, 1, 0)` |
| 账号 A、账号 B 各在线，另有一个独立匿名访客 | `(3, 2, 1)` |
| 同键最后一个有效登录连接离开，但匿名页仍在线 | 该账号无其他连接时从用户集合移除，此键开始贡献 1 个访客 |
| 同键连接账号 A、账号 B | 两个账号计 2 个用户，该键不计访客 |

这些是统计身份，不承诺自然人去重。不同站点现有存储键不同、不同 Origin 存储隔离、隐私模式、清除存储及无法持久存储时，都可能产生多个匿名统计键；本期保留现有标识，不迁移历史访客、不新增跨域身份跟踪。`fingerprint` 可伪造，统计结果不能用于鉴权或证明真实访客质量。

## 3. 身份接入方案

本站 accessToken 继续只通过 HTTP `Authorization: Bearer <token>` 发送，不放在 WebSocket URL、子协议、消息、Cookie 或浏览器持久存储中。

浏览器原生 `WebSocket` 构造器提供 URL 和子协议参数，没有任意 Header 参数，见 [WHATWG WebSocket 接口定义](https://websockets.spec.whatwg.org/#the-websocket-interface)。因此先用现有 HTTP 请求通道申请短期票据，再在 WebSocket 首条消息消费票据；这只是在线统计用途的授权衔接，不产生新的本站登录方式。

1. 前端通过 HTTP 申请一次性 `ticket`；已登录时使用内存中的现有 Bearer，匿名时不发送 Authorization。
2. 后端核验站点、来源、参数及可选登录身份，签发 30 秒有效的随机票据。申请成功不增加人数。
3. 前端建立 WebSocket，在打开后立即发送 `join`；连接核验成功前不计数、不接收统计快照。
4. 后端比较握手 Origin 与票据绑定来源，并重新核验原会话；原子消费票据后登记连接，推送首次快照。
5. 已消费、过期、用途或来源不符的票据不能重用。重连必须重新申请；票据只保留在内存，用后清除，不记录其原文。

Redis 票据键使用现有应用前缀加 `online:ticket:<票据摘要>`，TTL 为 30 秒。载荷保存站点、来源、统计标识、可空的 userId，以及登录时的原 Token 摘要与到期时间，不复制 accessToken 原文。只允许用票据关联 userId 的 Sa-Token 会话核对摘要与有效性，不扫描全部用户或全部 Redis 键。

连接后的会话校验不依赖线程当前请求或 `StpUtil.getTokenValue()`，必须使用连接核验时确认的原会话。现有 `SessionManager.originalToken()` 同时要求最近 300 秒认证，不能原样调用，否则普通在线连接超过五分钟就会被误拒绝；已补足 `requireOriginalActive(userId, tokenHash, expiresAt)` 按原会话引用核验有效性的能力，保留现有敏感操作的最近认证要求。

## 4. HTTP：申请在线连接票据（已实现）

<a id="online-ticket"></a>

| 项目 | 约定 |
| --- | --- |
| 完整路径 | `POST /api/v1/analytics/online/tickets` |
| Content-Type | `application/json` |
| 访问要求 | 公开，可选 Bearer；携带时必须属于启用账号的有效本站会话 |
| 成功响应 | HTTP 201；`Cache-Control: no-store` |
| 并发版本 | 无 `If-Revision`、`X-Revision`，不涉及业务资源编辑 |
| 限流 | 每可信 IP 每 60 秒 120 次、每浏览器统计键每 60 秒 30 次；复用 RedisRateLimiter，同请求各维度只计一次，超限返回 429 和 Retry-After |

### 请求参数

| 参数 | 位置/类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `Authorization` | Header/string | 否 | `Bearer <site-token>`；无效时返回 401，不静默按访客签发 |
| `Origin` | Header/string | 是 | 浏览器提供；必须是明确允许的前端来源，并匹配站点基址 |
| `fingerprint` | Body/string | 是 | 复用当前前台随机统计标识，ASCII `[A-Za-z0-9-]{16,150}`；禁止 userId、visitorId、会话 ID 或 Token 冒充此字段 |
| `siteCode` | Body/string | 是 | `home`、`blog`、`cv` 之一；不接受 `admin` |
| `pagePath` | Body/S(2048) | 是 | 经现有 SitePathUtils 规范化的站内路径，只用于站点路径前缀核验；不含 query、fragment、凭据或敏感票据 |

只接受声明字段，无查询参数。未知/重复属性、错误类型、空白值及缺失字段沿用现有 `400/VALIDATION_ERROR`。来源、站点和路径匹配复用 `PublicSiteProperties.requireSite`；敏感完成页使用配置的该站点基础路径申请，不上报其流程路径。此入口不校验文章可读性、不采集页面信息、不创建或更新访客数据库记录。

```http
POST /api/v1/analytics/online/tickets
Origin: https://blog.example.test
Authorization: Bearer <site-token>
Content-Type: application/json

{"fingerprint":"d681988a-cbd0-4ef6-bdec-f84bfa234e16","siteCode":"blog","pagePath":"/articles/first-leaf"}
```

示例 Origin 须在部署配置中明确允许，示例站点基址为 `https://blog.example.test`。匿名请求省略 Authorization，Body 不变。

### 响应模型 OnlineTicket

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ticket` | string | 使用 TokenUtils 生成的 43 位 URL 安全随机串；仅用于一次 join |
| `expiresIn` | integer | 固定 30，单位秒；消费后立即失效，不代表连接只能保持 30 秒 |

```json
{
  "code": "OK",
  "msg": "成功",
  "data": {"ticket": "<43-character-single-use-ticket>", "expiresIn": 30},
  "errors": []
}
```

票据值为占位说明，非可用凭据。其他错误：`401/UNAUTHENTICATED` 表示会话失效；`403/ACCOUNT_DISABLED` 表示账号禁用，沿用现有身份校验语义；`403/FORBIDDEN` 表示来源不允许或站点不匹配；`429/RATE_LIMITED` 表示限流；配置错误、Redis 或身份查询依赖不可用时为 `503/SERVICE_UNAVAILABLE`，不签发伪成功票据。

## 5. WebSocket：加入与接收实时人数（已实现）

<a id="online-websocket"></a>

| 项目 | 约定 |
| --- | --- |
| 外部完整路径 | `wss://<API主机>/api/v1/ws/online`；本地 HTTP 开发对应 `ws://` |
| 服务端注册路径 | `/ws/online`；复用 `/api/v1` context-path，不重复拼接 |
| 传输 | 原生 WebSocket、UTF-8 JSON 文本；不使用 STOMP、SockJS、消息代理或额外前端库 |
| 握手 | HTTP GET Upgrade 成功后为 101；不接受查询参数、accessToken 或普通 Cookie 身份 |
| 来源 | 显式核验 Origin 白名单，拒绝缺失、`null` 或不允许的 Origin；再在 join 时与票据来源逐项匹配 |
| 加入期限 | 建连后 5 秒内成功 join；否则关闭且不计数 |
| 消息限制 | 单条客户端消息最多 1KiB，拒绝二进制帧、未知类型、未知/重复字段及错误类型；每连接每 60 秒最多 30 条客户端业务消息，超限关闭，不影响其他连接 |

HTTP 握手放行仅允许该精确路径的合法 Upgrade，不能成为普通 GET 绕过身份校验的入口。握手阶段按可信 IP 每 60 秒最多 120 次进行限流，超限以 429 和 Retry-After 拒绝；普通 GET 返回 `400/VALIDATION_ERROR`，非法 Origin 返回 403。WebSocket 消息不经过普通 Controller 的请求参数校验，必须在消息入口执行上述边界规则。升级失败浏览器通常只得到连接错误，不能依赖 JavaScript 读取握手 JSON 或响应头。

### 5.1 首条客户端消息：join

```json
{"type":"join","ticket":"<43-character-single-use-ticket>"}
```

只允许一次成功 join；加入前其他消息、重复 join、票据无效或会话已撤销均拒绝。前端不能直接提交 userId、登录标志或用户人数。票据消费和登记期间连接若关闭，必须回收已登记状态；票据一经消费不恢复，失败重连申请新票据。

### 5.2 服务端人数快照：online.count

```json
{
  "type": "online.count",
  "code": "OK",
  "msg": "成功",
  "data": {
    "onlineCount": "8",
    "userCount": "3",
    "guestCount": "5",
    "serverTime": "2026-11-01T02:00:00.000Z"
  },
  "errors": []
}
```

这是 WebSocket 专用消息包络：保留 Result 的 `code/msg/data/errors`，另加 `type` 区分消息；不改变现有 HTTP Result 模型。`data` 即第 2 节的四个必有、非 null 字段，不返回连接清单、userId、fingerprint、IP、Token 或票据。

- join 成功立即给该连接发送当前快照，即使人数未变；首次消息也代表加入成功。
- 加入、退出、关闭、超时清理或原会话失效导致三项计数变化时，向全部已加入连接广播完整快照。正常运行时变化后 1 秒内发出，不要求客户端轮询查询。
- 数字不变时不向其他连接重复广播。前端整份替换快照，不自行加减，也不把历史 PV/UV 填入在线字段。
- 同一连接的消息发送必须串行，状态变更、快照生成及广播顺序要一致；采用 Spring WebSocket 时使用其已有会话发送能力处理并发写入，不复制参考实现的无结果异步发送。

### 5.3 心跳

客户端加入成功后每 25 秒发送：

```json
{"type":"ping"}
```

服务端确认心跳并单发：

```json
{"type":"pong","code":"OK","msg":"成功","data":null,"errors":[]}
```

这是应用 JSON 心跳，不是 WebSocket 协议控制帧。心跳不会增加人数、延长本站 Token 有效期、刷新最近认证时间或产生浏览记录。客户端 10 秒未收到对应 pong，关闭旧连接后重新申请票据；每次只允许一个待确认心跳。

服务端记录最近一次合法 join/ping 的接收时间，75 秒未收到心跳即过期，每 5 秒检查一次，最晚约 80 秒回收掉线成员。超过期限的连接不能通过迟到 ping 复活。每 25 秒重新核验原登录会话和账号状态，结合检查周期，正常依赖条件下撤销后最晚约 30 秒移除登录连接；不是只在首次 join 时检查。

### 5.4 错误与关闭

可发送消息时，服务端先发送错误包再关闭；连接已损坏、超大帧或传输失败时不保证错误包送达。

```json
{"type":"error","code":"ONLINE_TICKET_INVALID","msg":"连接票据无效，请重新连接","data":null,"errors":[]}
```

| 条件 | 业务码 | 关闭码与前端动作 |
| --- | --- | --- |
| 票据格式错、过期、已消费、来源或用途不匹配 | 新增 `ONLINE_TICKET_INVALID` | 1008；重新申请票据，不重用旧值 |
| 原 Token 已注销/过期或不再属于原用户 | `UNAUTHENTICATED` | 1008；清除本页内存会话后按匿名身份重新申请 |
| 原账号被禁用/删除 | 沿用当前账号状态错误语义 | 1008；清除本页会话，后续以明确匿名请求重新申请，不恢复原登录身份 |
| join 超时、重复 join、消息类型/格式非法 | `VALIDATION_ERROR` | 1008；停止当前协议错误连接，不无限重试同一错误 |
| 客户端消息频率超限 | `RATE_LIMITED` | 1008；停止该连接，至少等待 60 秒再申请 |
| 客户端消息超过 1KiB | 不保证错误包 | 1009；修正发送内容 |
| 75 秒心跳期限届满 | 不保证错误包 | 私有关闭码 4000；重新申请票据 |
| Redis、账号查询或发送依赖故障 | `SERVICE_UNAVAILABLE`（能发送时） | 1011；显示连接中断，按重连规则恢复 |
| 正常离开、组件卸载、主动切换身份 | 无错误包 | 1000；清理连接和全部计时器 |

错误码不作为新的 HTTP 状态码使用。`ONLINE_TICKET_INVALID` 已加入 WebSocket 消息业务码清单；其他错误复用当前契约。不能把 1006 当作服务端主动发送的关闭码，也不能在依赖故障时将登录身份直接判成匿名或向页面伪造零人数。

## 6. 登录态变化与前端展示

1. 每个页面实例只维护一条在线连接，由应用或持续存在的布局管理；路由切换复用，Blog 统计卡片只读取人数状态。初始状态为“连接中”，不预填 `0`。
2. Blog 在 `acceptSession` 完成后、`clearSession` 执行后重建连接：先结束旧连接，再用最新 HTTP 会话申请新票据，覆盖密码登录、OAuth 登录、主动退出、401 和账号安全变更。异步申请完成前若身份又变了，丢弃旧结果，不能重新挂回旧身份。
3. 一个标签页的登录不向其他标签页传播 Token。匿名标签页仍匿名，人数去重只在服务端按第 2 节执行。其他设备的会话独立；某 Token 注销后，账号仍有其他有效前台连接就继续计为 1 个用户。
4. Home、Cv 当前没有本站内存登录态，按匿名方式参与；不从 Blog、Admin Cookie 或存储恢复用户身份。Cv 只为在线统计生成随机标识，不顺带新增 PV 采集。保持各站点当前标识；无持久存储时在页面实例内复用一次生成的标识。
5. 仅在 Blog 当前实际使用的 `SidebarCard.vue` “站点统计”卡片显示“当前在线”“登录用户”“未登录访客”三行，并标注“三站合计”。三个站点页脚均不展示在线人数；Home/Cv 只匿名登记；不新建后台监控页。
6. 连接中断时显示“在线人数连接中断”；若保留上次数字，必须标注“上次数据”，不能继续标为实时。恢复后使用首份新快照替换。数量更新不抢焦点、不弹重复消息，读屏状态使用适当的礼貌通知。
7. 网络/1011/掉线关闭后按 1、2、5、10、30 秒的上限退避并加入少量随机延迟，成功后重置；429 尊重 HTTP Retry-After，握手错误不可读时按连接错误退避。浏览器 offline 时暂停，online 后恢复；协议错误停止自动重试。只保留一个重连计时器。
8. `pagehide`、布局/应用卸载时关闭连接并清理心跳、pong 等待和重连计时器；从往返缓存恢复的 `pageshow` 重新连接。旧连接的延迟回调不能覆盖新连接状态。

## 7. 实现位置与部署限制

### 7.1 最小实现与依赖

首期使用单后端实例的内存连接登记与去重状态，Redis 只负责一次性票据、现有登录会话与限流。关闭、异常、发送失败、超时与身份失效统一做幂等移除；同一连接只清理一次，不独立维护容易与集合失配的连接总数。

采用 Spring 的 `TextWebSocketHandler` 与握手校验接入已有应用组件，参见 [Spring WebSocket 服务端文档](https://docs.spring.io/spring-framework/reference/web/websocket/server.html)。只在 `server/pom.xml` 增加由当前 Boot BOM 管理的 WebSocket starter，不升级 Java/Boot、不引入 STOMP、消息队列或新的 JSON 框架。序列化沿用现有 Jackson 3 配置；Spring API 的并发发送限制见上述官方文档。

| 影响位置 | 已落实改动 |
| --- | --- |
| `Backend/server/controller`、`service`、`service/impl` | 增加票据申请 HTTP 入口及对应业务协调；原会话/账号核验使用现有 Mapper 和身份规则，不新增数据库表 |
| `Backend/server/config`、新增 `websocket` 职责包 | 注册 WebSocket、Origin/握手校验、首条 join、心跳、消息校验、发送和生命周期清理；依赖业务模型的在线登记放 server，不塞进业务 Service 包 |
| `Backend/common/store`、`session` | 独立在线票据存储和原会话有效性核验所需的最小能力；不改 OAuth/订阅票据生命周期，不撤除敏感操作最近认证要求 |
| `Backend/entity/dto`、`vo`、必要内部模型 | 声明票据请求、票据响应、在线快照及连接绑定模型；按模块依赖边界放置，不为在线状态创建实体/Mapper/XML |
| `AuthWebConfig`、请求字段白名单及现有限流入口 | 只新增两条准确入口及所需白名单；可选 Bearer 与握手特殊处理分别实现，WebSocket 不绕过消息校验 |
| `Front/Front-Blog/src/api.js`、`session.js`、`tracking.js`、`view/Layout/index.vue`、`components/SidebarCard.vue` | 加入票据模型校验、复用随机标识、连接状态与生命周期、身份变更通知和站点统计卡片的三项人数展示；保持现有静态统计字段不变 |
| `Front/Front-Home/src/App.vue`、`api.js`、`tracking.js`；`Front/Front-Cv/src/App.vue`、`api.js` | 各工程按既有结构接入匿名在线连接，不展示人数；复用已有能力，不另起前端框架或共享包工程 |
| 三个参与前台的 `vite.config.js` 与实际反向代理 | 开发代理启用 WebSocket 转发；生产转发 Upgrade/Connection、保留 `/api/v1/ws/online` 路径，并让 Origin 验证基于实际浏览器来源 |
| 现有测试、接口/依赖/运行文档 | 增加真实隔离及传输故障行为验证；同步公开白名单、消息协议、运行条件、路由数与实际验收结果 |

WS 地址从既有 API 根地址推导，仅将协议映射为 `ws/wss`，路径追加一次 `/ws/online`；不能固定 `location.host`，因为当前前后端允许独立部署。生产使用 TLS，代理空闲超时须大于服务端约 80 秒清理窗口，并核验开发代理是否改写 Origin，避免放宽生产来源白名单。

### 7.2 保持与暂不实施

- 在线状态不落 MySQL，不建立历史在线曲线、在线用户清单、踢人接口或新的后台权限；也不增加 HTTP 轮询人数接口，首次快照由加入成功消息提供。
- 不改 `blog/statistics` 的 PV/UV、文章阅读数、访客封禁与删除语义。访客统计标识封禁仍只约束原页面采集入口，不扩展为在线连接的身份封禁。
- 不套用 Spring Cache 查询缓存；在线快照来自当前登记状态。Redis/数据库故障导致原会话无法确认时关闭对应连接并提示故障，不把故障当作自然人数变化或有效匿名认证。
- **首期只支持单后端实例。** 内存人数会在进程重启后重新登记，重连期间会短暂偏低；不能在多个实例前加负载均衡后声称全局一致，粘性会话也不能解决全局去重。若实际部署已要求多实例，须在实施前将本节改为共享在线成员、过期回收和跨节点广播方案，并增加隔离验收；本次不预建该体系。
- 不承诺服务器宕机、网络分区、浏览器停止计时或依赖不可用时仍满足“1 秒广播”与固定离线检测时限；页面通过连接状态区分可用快照和中断。

## 8. 验证范围与检查记录

以下为验证场景；实际执行结果及限制见本节末尾与[后端运行说明](后端运行说明.md#online-runtime)。

| 验收场景 | 核心断言 |
| --- | --- |
| 票据入口 | 匿名与有效 Bearer 签发正确；无效 Token 不降级；字段、Origin、站点路径和两项限流生效；票据请求不写 PV/访客表 |
| 票据消费 | 首次成功、过期拒绝、并发消费只有一次成功、跨来源/跨用途拒绝；申请不增人数，失败 join 无残留 |

| 前端真实生命周期 | Blog 卡片的三项人数与首次快照展示、失败状态、密码/OAuth 登录与退出切换、跨页复用、重连新票据、旧回调隔离及卸载/往返缓存清理 |
