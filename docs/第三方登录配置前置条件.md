# GitHub、Gitee、QQ 第三方登录配置前置条件

本文按已提供的服务器和域名信息填写，覆盖 DriftingLeavesV2 的 Blog 和 Admin。每个平台只在后端填写一套应用凭据和一个登记回调。两端共用账号绑定，各自发起授权并建立会话。平台要求核对于 2026-11-06。

## 站点和服务器填什么

| 项目 | Blog | Admin |
| --- | --- | --- |
| DNS 主机记录（直接解析时） | `blog`，A 记录值 `<服务器公网 IPv4>` | `admin`，A 记录值 `<服务器公网 IPv4>` |
| 完整域名 | `blog.driftingleaves.xyz` | `admin.driftingleaves.xyz` |
| 站点地址 | `https://blog.driftingleaves.xyz` | `https://admin.driftingleaves.xyz` |
| 登录页 | `https://blog.driftingleaves.xyz/login` | `https://admin.driftingleaves.xyz/login` |
| 前端授权完成页 | `https://blog.driftingleaves.xyz/oauth/complete` | `https://admin.driftingleaves.xyz/oauth/complete` |
| 要转发的 API 路径 | `/api/v1/blog/` | `/api/v1/admin/` |
| 同机反代目标 | `http://127.0.0.1:5922` | `http://127.0.0.1:5922` |

主域名为 `driftingleaves.xyz`，网站主页为 `https://driftingleaves.xyz`，服务器公网 IPv4 为 `<服务器公网 IPv4>`，后端监听端口为 `5922`。如果主域名也由这台服务器直接提供 HTTPS，DNS 的 `@` 记录可同样使用 A 记录指向 `<服务器公网 IPv4>`。已有代理入口的域名沿用其 DNS 配置。第三方平台表单填写网站的 HTTPS 域名和下文的完整回调 URL。

## 先准备项目环境

- **两个 HTTPS 站点。** 后端的 `BLOG_BASE_URL` 和 `ADMIN_BASE_URL` 与上表的浏览器访问地址一致。两个站点的 `/oauth/complete` 都应能直接打开对应的前端完成页。
- **同一个后端。** Blog 和 Admin 将上表的 API 路径原样转发到同一后端，保留回调查询参数、Cookie 和 Set-Cookie。如果 Nginx 与后端同机，在 Blog HTTPS 站点使用 `location /api/v1/blog/`，在 Admin HTTPS 站点使用 `location /api/v1/admin/`，两处均设置 `proxy_pass http://127.0.0.1:5922;`。反代目标末尾不加路径或斜杠，以保留原始 URI。容器或跨机部署使用反代实际可达的后端地址，端口为 `5922`。
- **后端依赖可用。** MySQL 保存本站用户与第三方绑定，Redis 保存图形验证码、授权流程、票据和会话。部署后端的机器需要能通过 HTTPS 访问所启用平台的换码和用户接口。GitHub 使用 `github.com` 和 `api.github.com`，Gitee 使用 `gitee.com`，QQ 使用 `graph.qq.com`。需要创建新本站账号时，还需配置 SMTP 以接收注册验证码。

## 各平台要准备什么

| 平台 | 申请入口与应用类型 | 准备资料及凭据 |
| --- | --- | --- |
| GitHub | [Developer settings → OAuth Apps](https://github.com/settings/developers)，创建 **OAuth App** | 可用个人账号，或使用对组织有管理权限的账号。准备应用名、网站主页和完整回调 URL。创建后复制 **Client ID**，并在应用设置生成 **Client Secret**。见 [GitHub 创建 OAuth App](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)。 |
| Gitee | 登录后打开 [Gitee 第三方应用](https://gitee.com/oauth/applications)，创建第三方授权应用 | 准备应用名、说明、网站主页和完整回调 URL，按创建页提示选择读取用户资料所需的权限。应用详情提供 **Client ID** 和 **Client Secret**。见 [Gitee OAuth 文档](https://gitee.com/api/v5/oauth_doc) 和 [JustAuth 的 Gitee 接入说明](https://www.justauth.cn/guide/oauth/gitee/)。 |
| QQ | 用 QQ 登录 [QQ 互联应用管理](https://connect.qq.com/manage.html#/)，完成开发者资质审核，创建 **网站应用** | 按主体类型提交个人或公司资料。准备可公开访问的网站、网站名称、域名、完整回调 URL 和适用的备案资料。创建后获取 **App ID** 和 **App Key**，分别填入项目的 Client ID 和 Client Secret。面向普通 QQ 用户上线前须通过应用审核并取得登录接口权限。见 [QQ 互联开发者注册](https://wiki.connect.qq.com/成为开发者/) 和 [网站应用准备工作](https://wiki.connect.qq.com/准备工作_oauth2-0/)。 |

### 平台后台表单怎么填

以下用 Blog 作为公开应用主页。只有确实需要更换登记端时，才选后文的 Admin 回调；已有应用可以保留原登记端和应用凭据。

| 平台 | 表单字段 | 填写内容 |
| --- | --- | --- |
| GitHub | Application name | `Drifting Leaves` |
| GitHub | Homepage URL | `https://blog.driftingleaves.xyz` |
| GitHub | Application description，可选 | `用于 Drifting Leaves 博客和管理控制台的账号绑定与登录。` |
| GitHub | Authorization callback URL | 从下表复制 GitHub 的完整 URL，Blog 和 Admin 选一列 |
| GitHub | Enable Device Flow | 不勾选，本项目使用网页授权 |
| Gitee | 应用名称、应用描述 | `Drifting Leaves`、`用于 Drifting Leaves 博客和管理控制台的账号绑定与登录。` |
| Gitee | 应用主页 | `https://blog.driftingleaves.xyz` |
| Gitee | 应用回调地址 | 从下表复制 Gitee 的完整 URL，Blog 和 Admin 选一列 |
| Gitee | 权限、应用图标 | 选择读取用户资料的权限（`user_info`）。表单要求图标时，上传你有权使用的站点 Logo |
| QQ | 应用类型、网站名称 | `网站应用`、`Drifting Leaves`（网站名称以实际首页和备案信息为准） |
| QQ | 网站主页、网站域名 | 主页填 `https://blog.driftingleaves.xyz`，单独的域名字段填 `blog.driftingleaves.xyz` |
| QQ | 网站回调地址 | 优先填下表的 Blog 完整回调 URL；若已有有效 Admin 登记回调，可沿用 |
| QQ | 备案号 | 按实际登记填写网站的完整备案号。个人或企业资料及联系人按实际登记填写。 |
| QQ | 网站介绍、应用图标 | 网站介绍可填 `Drifting Leaves 是一个个人博客，QQ 登录用于绑定本站账号和后续登录。`。图标上传站点 Logo。网页上的 QQ 登录按钮另用腾讯官方标识 |

QQ 的申请主体、联系人及各平台生成的应用凭据以你的控制台或备案记录为准。Gitee、QQ 的字段如随控制台版本调整，主页填浏览器地址，回调字段填下表的完整后端 URL。见 [GitHub 创建 OAuth App](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)、[Gitee 第三方应用说明](https://www.justauth.cn/guide/oauth/gitee/) 和 [QQ 互联创建应用](https://wiki.connect.qq.com/__trashed-2/)。

### QQ 送审前再核对

- **备案和可访问性。** QQ 互联的常规审核要求网站和回调地址对应的域名已完成备案，填报信息与备案一致。境外网站没有国内备案时，腾讯另列有国际域名申请流程，应按该流程提交材料并确认审核结果。回调需用公网可访问的域名，避免填写 localhost 或带端口的地址。见 [应用审核规范](https://wiki.connect.qq.com/网站审核规范/)、[境外网站申请问答](https://wiki.connect.qq.com/常规问题-20170322/) 和 [回调地址校验说明](https://wiki.connect.qq.com/回调地址常见问题及修改方法/)。
- **审核页面。** 腾讯要求网站已可正常访问，QQ 登录功能能走通，并在显眼位置使用腾讯提供的标准标识。当前项目的 [Blog 登录表单](../Front/Front-Blog/src/components/AuthForm.vue) 和 [Admin 登录页](../Front/Front-Admin/src/views/Login.vue) 使用通用平台按钮，没有接入 QQ 官方标识。准备送审时应先补上标识，再用平台允许的测试 QQ 号走通授权和本站绑定。见 [QQ 网站前端页面规范](https://wiki.connect.qq.com/移动应用接入流程（改）test/) 和 [申请注册问答](https://wiki.connect.qq.com/常规问题-20170322/)。

## 本项目的回调与环境变量

**每个平台从下表选一列。** 选 Blog 时，Admin 用户依然可以从 Admin 登录页发起授权。平台先回调到 Blog API，后端再按本次流程转回 Admin。若选 Admin，Blog 发起授权时也会按同样方式转回 Blog。

| 平台 | Blog 登记回调 | Admin 登记回调 |
| --- | --- | --- |
| GitHub | `https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/GITHUB/callback` | `https://admin.driftingleaves.xyz/api/v1/admin/auth/oauth/GITHUB/callback` |
| Gitee | `https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/GITEE/callback` | `https://admin.driftingleaves.xyz/api/v1/admin/auth/oauth/GITEE/callback` |
| QQ | `https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/QQ/callback` | `https://admin.driftingleaves.xyz/api/v1/admin/auth/oauth/QQ/callback` |

将选中的完整 URL 同时填到平台回调设置和后端对应的 `*_REDIRECT_URI`。保持平台名大写，URL 不带查询参数、`#` 或末尾斜杠。前端完成页由项目按发起端确定。继续使用原应用可以保留 QQ 的 OpenID 等已有身份映射。见 [QQ 互联关于不同 App ID 的说明](https://wiki.connect.qq.com/常规问题-20170322/)。

### 后端进程环境变量模板

以下示例选 Blog 作为三个平台注册的回调。部署时通过后端环境变量提供应用凭据。Gitee 和 QQ 在申请到凭据后单独启用。

```dotenv
SPRING_PROFILES_ACTIVE=prd
SERVER_PORT=5922
HOME_BASE_URL=https://driftingleaves.xyz
BLOG_BASE_URL=https://blog.driftingleaves.xyz
ADMIN_BASE_URL=https://admin.driftingleaves.xyz

OAUTH_GITHUB_ENABLED=true
OAUTH_GITHUB_CLIENT_ID=<GitHub OAuth App 的 Client ID>
OAUTH_GITHUB_CLIENT_SECRET=<GitHub OAuth App 的 Client Secret>
OAUTH_GITHUB_REDIRECT_URI=https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/GITHUB/callback

OAUTH_GITEE_ENABLED=false
OAUTH_GITEE_CLIENT_ID=<Gitee 第三方应用的 Client ID>
OAUTH_GITEE_CLIENT_SECRET=<Gitee 第三方应用的 Client Secret>
OAUTH_GITEE_REDIRECT_URI=https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/GITEE/callback

OAUTH_QQ_ENABLED=false
OAUTH_QQ_CLIENT_ID=<QQ 互联网站应用的 App ID>
OAUTH_QQ_CLIENT_SECRET=<QQ 互联网站应用的 App Key>
OAUTH_QQ_REDIRECT_URI=https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/QQ/callback
```

若某个平台选的是 Admin，只换该平台的 `*_REDIRECT_URI`，两端的基址都保留。若服务器已覆盖 `SERVER_PORT`，沿用实际端口并与反代配置对齐。真实应用密钥不放进 Git 或前端构建。若后端 JAR 会对外分发，打包前将本地 `application-prd.yml` 的密钥默认值留空，部署时通过后端环境变量或部署平台的密钥管理注入。现有数据库、Redis、SMTP 连接仍按服务器现有配置填写，见 [后端运行说明](后端运行说明.md)。

## 配好后怎么确认

1. 打开 [Blog 平台列表](https://blog.driftingleaves.xyz/api/v1/blog/auth/oauth/providers) 和 [Admin 平台列表](https://admin.driftingleaves.xyz/api/v1/admin/auth/oauth/providers)，检查 JSON 的 `data` 是否包含已启用平台，再到两端登录页确认按钮显示。列表为空时检查开关、凭据、回调和 HTTPS 基址。若返回前端 HTML 或 404，先检查对应站点的 API 反代。
2. 用已有本站账号登录，到个人设置绑定一次第三方账号。发起绑定要求最近 5 分钟内完成过登录认证。没有本站账号时，先完成邮箱验证注册。
3. 在两端分别使用同一个第三方账号发起登录，确认两端都能访问各自的个人资料。OAuth 登录无需图形验证码，并限制为每分钟三次。用于测试 Admin 的本站账号还需有 `admin:access` 权限。QQ 正式对外开放前，另用普通 QQ 账号验证审核后的登录能力。

运行环境与反代要求见 [后端运行说明](后端运行说明.md#文件邮件与-oauth)，授权流程见 [API 开发约定](API_CONTRACT.md#oauth-flow)。
