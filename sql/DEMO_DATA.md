# V2 演示数据导入说明

[demo_data.sql](demo_data.sql) 为当前项目生成虚构数据，供前后台列表、分页、筛选、详情和统计图表使用。它只增加演示记录，不重建表，不修改已有管理员、站点配置、角色权限或菜单。

## 导入前提

- 目标为 MySQL 8.0.16+ 的 V2 开发/测试库，已有完整表结构与基础 author/member 角色。
- 旧库须先补齐 [评论与登录地域升级](migrations/20261101_client_location.sql) 和 [留言地域升级](migrations/20261102_message_client_location.sql) 中缺少的列。已经升级的库不要重复执行迁移。
- 导入前备份目标库。脚本不包含 `USE`，在数据库工具中选择正确的 V2 库后执行整份文件。
- 连接账号需要相关表的 SELECT、INSERT 以及 CREATE TEMPORARY TABLES 权限；脚本中的 UPDATE 只更新本连接的临时映射表。

所有演示账号以 `v2_demo_` 开头，文章等 slug/统计指纹以 `v2-demo-` 开头，评论/留言正文含 `[V2 演示 Cxx/Mxx]` 标识。日志用 `operation_data.demoKey` 标记。

账号没有密码或 OAuth 绑定，不能用来登录，也没有管理员角色；请使用已有账号进行后台检查。邮箱和外部链接使用示例域名，IP 使用文档专用地址，省市为虚构展示值，不代表这些地址的真实地域。音乐默认隐藏，不会加入前台播放器；替换为可播放的真实音频 URL 后再启用。

文章没有封面或附件引用，文件和 OAuth 绑定不伪造。主页与简历可另行使用已有 [cv_demo_data.sql](cv_demo_data.sql)，该脚本保留已有资料；它内置 `USE driftingleaves`，使用其他库名时须先调整。

## 导入方法

在 Navicat、DBeaver 等工具中选择目标 V2 开发库，打开 `demo_data.sql`，使用 UTF-8 执行完整脚本，并开启“遇错停止”。也可在 MySQL 客户端中执行：

```sql
USE driftingleaves;
SOURCE D:/CodingFiles/Blog/DriftingLeavesV2/sql/demo_data.sql;
```

脚本按 UTC 写入时间，导入成功后恢复原会话时区。末尾会输出账号、文章、评论、留言、访客、浏览明细的数量，首次完整导入应分别为 **8、24、36、32、18、240**。

若出现错误，立即停止后续语句，在同一连接执行 `ROLLBACK;`，不要忽略错误继续执行末尾的 `COMMIT`，也不要使用客户端的 `--force`。事务只在最终 COMMIT 时持久化；MySQL 不会因普通语句错误自动回滚整笔事务。

**导入成功后重启后端，再刷新页面。** 直接写 SQL 不会触发应用缓存失效。导入不会发送邮件，也不创建 Redis 确认/退订票据；邮件验证、实际音频播放和真实用户行为仍需通过应用测试。

## 重复执行与验证

同一份脚本连续导入不会增加重复记录，也不会重置已修改的文章标题、审核状态、访客限制等。它按演示用户名、slug、正文标识、指纹和日志 demoKey 判断记录；手动改掉这些匹配字段或删掉记录后，再导入可能重新补入原始样例。时间锚点沿用本批首个演示访客，因此再次导入不会自动刷新图表日期。

`DemoDataIntegrationTest` 使用仓库既有隔离设施，新建临时 MySQL/Redis，在初始化基线上连续导入两次，核对数量、关联、私密继承、不重复及已有记录/后续编辑的保留。它不连接现有业务服务：

```powershell
mvn -B -ntp -f Backend/pom.xml -pl server -am test `
  '-Dtest=DemoDataIntegrationTest' `
  '-Dsurefire.failIfNoSpecifiedTests=false' `
  '-Dtest.mysql.bin=D:/CodeEnvironment/MySQL/mysql-8.0.34-winx64/bin/mysqld.exe' `
  '-Dtest.redis.bin=D:/CodeEnvironment/Redis/redis-server.exe'
```
